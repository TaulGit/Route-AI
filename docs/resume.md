# RouteAI 简历项目经历（2026-10-26 重构后）

**RouteAI — 基于 LangGraph 的可恢复多 Agent 旅行规划系统**

**2026.03–2026.06；2026.10 重构**

- **多 Agent 协作与工具决策：**基于 LangGraph 构建 Coordinator–Worker 工作流，通过 `Send` 动态分发专题检索任务、reducer 归并来源证据；为检索 Agent 实现原生 Tool Calling 循环、严格参数校验、失败反馈与调用上限，支持根据工具结果调整检索词。
- **持久执行与人机协作：**使用 SQLite Checkpointer 与 `interrupt/Command` 实现需求澄清、行程审核和修改后重规划；支持跨进程恢复，以会话归属校验和中断 ID 条件更新防止越权读取与重复审核。
- **结构化生成与可靠性：**使用 Pydantic 约束研究任务和行程输出，强制绑定已检索 POI ID；设计地点、时间与估算预算校验及最多 2 次修复闭环，对无证据、超约束和工具失败显式返回诊断与估算标识。
- **可观测与评测：**基于实际节点事件实现 SSE 进度和持久日志，支持页面刷新恢复；构建无网络离线评测集，17/17 场景、109/109 检查通过，另覆盖工具循环、SQLite 恢复、断流及用户隔离回归。

## 30 秒口述

我把旅行规划从固定调用链改成了有边界的多 Agent 工作流：主管拆分任务，多个检索 Agent 各自根据工具结果决定是否改词重试，规划器只引用工具提供的地点。结构化输出之外，再用代码检查时间和估算预算，并限制修复次数。用户补信息和审核时，工作流真正暂停、落盘，服务重启可以继续；我也做了离线评测和两进程恢复测试来验证这些能力。
